# TestNG and q4j Test Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run every module's tests on TestNG with q4j `testng` extensions, log through SLF4J/Log4j 2 with per-scenario files, and run end-to-end scenarios in parallel without losing a single test case.

**Architecture:** `archgate.java-conventions` switches modules to TestNG one group at a time through a temporary `TESTNG_PROJECTS` set, adds q4j and a shared test resource and test source directory under `config/`. The end-to-end test gets a `ScenarioLog` helper (MDC + Allure steps + per-run log file) and a parallel data provider. A comparison script outside the repo proves test-case parity against the baseline captured on `main`.

**Tech Stack:** Java 21, Gradle 9, TestNG 7.12 (through `dev.quokkify:testng:0.12.2`), SLF4J 2 + Log4j 2.26 (`log4j-slf4j2-impl`), Allure TestNG, AssertJ.

**Spec:** `docs/superpowers/specs/2026-10-29-testng-q4j-design.md`

## Global Constraints

- q4j version `0.12.2`, artifact `dev.quokkify:testng`, `testImplementation` only. No `implementation`/`api`/`compileOnly` configuration of any module gains q4j, SLF4J, Log4j or Allure (AGENTS.md contract 4).
- `RetryListener` is never registered.
- Every assertion and assertion message in migrated tests stays; only the annotation and lifecycle API change.
- `-PfixtureTools`, `FixtureTools.fromSystemProperty` and the `compared` logic of `FixtureEndToEndTest` stay unchanged (fail closed).
- Test thread defaults: `TEST_THREAD_COUNT=4` (shared `testng.properties`), `DATA_PROVIDER_THREAD_COUNT=4` (`:testing:test` environment).
- Per-run logs: `build/test-logs/<scenario>/<tool>-run<run>.log` relative to the module directory; `<tool>` is `maven` or `gradle`.
- Allure results: `build/allure-results` of each module.
- Baseline (on `main`, 2026-10-29): `./gradlew clean build --no-build-cache` = 101.4 s; test result XML saved under `$BASELINE` = a local copy of the baseline test result XML, outside the repository (not committed). Only these directories are real projects there: `engine_api` (10), `engine_core` (98), `backends_archunit` (146, of which 3 are `archfixtures.*`), `backends_classgraph` (22), `backends_javaparser` (15), `integration_gradle-plugin` (5), `integration_maven-plugin` (10), `testing_build` (70). Others are stale build directories from the old layout and are ignored.
- Commits: Conventional Commits, body ends with `Refs #23` and the `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` line.

## Review Focus

1. **Silent drop of tests.** A module whose JUnit tests are not migrated, or a TestNG class that Gradle no longer discovers, still builds green. Guard: `compare-results.sh` (Task 1) after every migration task; zero tolerance for a missing class or a lower count.
2. **Shared instance state under `parallel=methods`.** TestNG shares one instance between methods; JUnit gave each method a fresh one. Any field written in `@BeforeMethod`/`@AfterMethod` or by a test (`CachingFunctionalTest.project`, `ApiVersionManifestTest.jars`, `@TempDir` fields) races. Guard: no mutable instance field survives migration — move it into the method or a try-with-resources; if impossible, the method gets `@SingleThread` and the reason in a one-line comment.
3. **Process-global state.** Tests that set system properties, the working directory, POSIX permissions (`RegistrationCheckTest`) or Gradle caches (`CachingFunctionalTest`) interfere when run concurrently. Guard: `@SingleThread` on those methods.
4. **`archfixtures` classes picked up as tests.** Gradle's TestNG detection scans class files; `archfixtures/assertions/*Test` carry `org.testng` annotations and would start running. Guard: `rules-archunit` test task `exclude 'archfixtures/**'`; parity script ignores `archfixtures.*`.
5. **Two SLF4J providers.** `rules-archunit` has `testRuntimeOnly slf4j-simple`; with `log4j-slf4j2-impl` from q4j SLF4J picks one at random and warns. Guard: drop `slf4j-simple`; Task 1's verification greps the test output for `SLF4J(W): Class path contains multiple`.
