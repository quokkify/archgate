# Как написать бэкенд или правило

[English](extending.md) · Русский

Эта страница — контракт между ArchGate и кодом, который к нему подключается: правилами (`ArchitectureRule`) и бэкендами (`AnalysisContext` вместе с его `ContextProvider`). README показывает, [как написать правило](../README.ru.md#как-написать-своё-правило); здесь перечислено, на что правило или бэкенд может полагаться и что оно обязано гарантировать.

## Что публично

- `archgate-api` (`dev.quokkify.archgate.api`) — публичный контракт. Его версию библиотека правил указывает в `Archgate-Api-Version` (см. [Библиотеки правил](configuration.ru.md#библиотеки-правил)).
- Бэкенды `archgate-context-archunit`, `archgate-context-javaparser` и `archgate-context-classgraph` публичны для правил, которые их используют.
- `archgate-core` — внутренний модуль. Его классы публичны только для того, чтобы их вызывали плагины Maven и Gradle. Совместимость для них не обещается, они могут измениться в любом релизе, так что не завись от них.

## Как проходит запуск

1. Core загружает правила из `META-INF/services/dev.quokkify.archgate.api.ArchitectureRule` и провайдеры из `META-INF/services/dev.quokkify.archgate.api.ContextProvider` с test runtime classpath.
2. `verify` каждого правила вызывается один раз, и все правила выполняются одновременно, по виртуальному потоку на правило.
3. Первое правило, которое запрашивает тип контекста, заставляет core вызвать провайдер этого типа. Для каждого типа должен быть зарегистрирован ровно один провайдер; ни одного или несколько — это ошибка «невозможно проверить». Контекст строится один раз, и один и тот же экземпляр передаётся всем правилам этого типа одновременно.
4. Когда все правила закончили, core закрывает каждый построенный контекст, который реализует `AutoCloseable`. Ошибка при закрытии — это ошибка «невозможно проверить».

## Правила

- `verify` должен быть безопасен при одновременном вызове из нескольких потоков на общем контексте. Состояние одного запуска держи в локальных переменных, а не в полях правила.
- Чтобы сообщить о нарушениях, бросай `ArchitectureViolation`, обычно через `checkViolations(expectedContract, violations)`. `AssertionError` тоже считается нарушением. `severity()` правила определяет, валит ли нарушение сборку при заданном `failOn`.
- Бросай `UnableToVerifyError`, когда правило не может дать надёжный ответ, например потому что нужных классов нет. Такая ошибка валит сборку при любом `failOn`, и отчёт не пишется. Любое другое исключение или ошибка из `verify` тоже превращается в ошибку «невозможно проверить».
- Никогда не проходи молча из-за того, что проверять было нечего: правило, которое ничего не проверило, должно бросить `UnableToVerifyError`, а не вернуть управление.
- Правилу нужен публичный конструктор без аргументов, и оно должно быть перечислено в файле services. Класс правила в модуле проверки, которого нет в списке, роняет запуск с ошибкой регистрации (см. [Регистрация](configuration.ru.md#регистрация)).

## Бэкенды

- `ContextProvider.type()` называет тип контекста, который он строит, а `create(ProjectLayout)` строит его. Зарегистрируй провайдер в `META-INF/services/dev.quokkify.archgate.api.ContextProvider`.
- Контекст общий для одновременно работающих правил, поэтому он должен быть потокобезопасным. Дорогие представления строй лениво и один раз, например под блокировкой или через мемоизирующий holder.
- `ProjectLayout.classDirs(scope)` может содержать каталоги обработанных ресурсов рядом с каталогами классов (Gradle держит их отдельно, Maven — нет) и пути, которых нет (модуль без main-классов). Пропускай несуществующее, не падай на нём.
- `ProjectLayout.sourceDirs(scope)` содержит только существующие каталоги. `ProjectLayout.classLoader()` видит test runtime classpath модуля проверки.
- Когда в области нечего анализировать под `rootPackage`, бросай `UnableToVerifyError` с сообщением о том, чего не хватает, чтобы правила, использующие это представление, не прошли, ничего не проверив.
- Если контекст держит ресурсы, реализуй `AutoCloseable`; core закроет его после запуска. Не закрывай его из правила.
- `buildTimes()` печатается в строке `Model build:` отчёта. Core сливает карты всех контекстов в одну и добавляет запись под простым именем класса каждого контекста, так что ключи всех бэкендов живут в одном пространстве имён. Начинай ключи с имени бэкенда, например `javaparser main`, чтобы два бэкенда не перезаписывали записи друг друга.
